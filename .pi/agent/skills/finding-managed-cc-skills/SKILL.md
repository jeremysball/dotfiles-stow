# Finding Managed CC Skills

## Why this exists

Claude Code installs plugins (taskferry, superpowers, frontend-design,
feature-dev, etc.) into versioned cache directories under
`~/.claude/plugins/cache/`. Each plugin update creates a new versioned
subdirectory (commit-hash style: `d1f903fbd013`, `a783d99248a7`, …) and the
old ones are kept for rollback. The pi agent harness doesn't follow plugin
lifecycle, so it can't resolve a skill by name alone — it needs an explicit
on-disk path.

**Do not symlink plugin cache directories into the pi skills tree.** Plugin
updates silently replace or prune versioned subdirectories; a symlink would
either point at a pruned path or get overwritten. The supported pattern is
to resolve the path fresh each time via `state.md`, regenerated by the
script in this skill's directory.

## When to use this skill

Trigger this skill when:

1. A task references a Claude Code plugin-managed skill (e.g.
   `superpowers:writing-skills`, `taskferry:using-taskferry`) and the pi
   sandbox doesn't have it registered in its own skill list.
2. `state.md` is missing or hasn't been refreshed in a long time.
3. The model encounters a skill name that wasn't in `state.md` on the
   last read — that's the detection signal that a new skill has appeared
   (e.g. after a plugin update added a new skill, or a new plugin was
   installed). Refresh `state.md` before proceeding.
4. A previously-cached path returns a missing file — a plugin update
   pruned the version that path pointed at. Refresh and re-resolve.

## File layout

This skill's directory contains:

- `SKILL.md` — this file (the procedure).
- `state.md` — auto-generated mapping of skill name → on-disk path.
  Never hand-edit. Regenerate via `refresh-state.sh`.
- `refresh-state.sh` — bash script that walks the plugin cache and
  rewrites `state.md` in place. Idempotent; cheap to re-run.

`state.md` is the only authoritative map at runtime; everything else is
noise.

## state.md format

`state.md` is a Markdown table with these columns:

| Column | Meaning |
|---|---|
| Skill | Skill name (from `name:` frontmatter). |
| Description | One-line description (from `description:` frontmatter). |
| Plugin | Plugin slug (e.g. `superpowers`, `taskferry`, `frontend-design`). |
| Version | The versioned cache subdir (`6.1.1`, `2.0.0`, `d1f903fbd013`, …). |
| Path | Absolute on-disk path to the skill's `SKILL.md`. |
| Resolved | UTC timestamp of when this row was selected as the newest version. |

A header above the table notes the refresh timestamp and the total skill
count. A blank line separates each row visually.

When multiple versions exist for the same skill, only **one row per skill**
appears in `state.md` — the newest. Newest is defined below.

## Picking the newest version

For each `(plugin, skill-name)` pair:

1. Find every versioned cache directory under
   `~/.claude/plugins/cache/<plugin>/<version>/skills/<skill-name>/SKILL.md`.
2. Sort by the **filesystem mtime of that `SKILL.md`**, descending.
3. Pick the first one (most recently modified).

Rationale: plugin updates overwrite the versioned subdir's contents; the
mtime of the deepest `SKILL.md` is the closest signal we have to "this
version is current." Content-hash version names (`d1f903fbd013`) are not
timestamps, so sorting by name is meaningless; the directory-level mtime
on the plugin root is coarser than the per-skill mtime.

This heuristic is approximate. If a plugin reinstalls without touching a
skill's mtime, the procedure may pick a stale version. If you suspect
that, regenerate `state.md` (the procedure is idempotent and cheap).

## Refresh procedure

Run the script in this skill's directory:

```bash
bash ~/.pi/agent/skills/finding-managed-cc-skills/refresh-state.sh
```

The script self-locates (writes `state.md` next to itself), so it works
from any cwd. It is idempotent — running it twice produces the same
result if the cache hasn't changed.

## Read procedure

When invoking a managed skill:

1. Read `state.md` to find the skill's path.
2. If the skill isn't in `state.md`, run `refresh-state.sh` first,
   then re-read `state.md`.
3. Use the `Path` column to `read` the actual skill's `SKILL.md` from the
   cache before applying the skill's instructions.
4. If the read fails (file missing), the cache may have been pruned by a
   plugin update. Run `refresh-state.sh`; the path may have shifted to a
   newer versioned subdir.

## Detection signal for new skills

If a task description or a referenced skill name is **not** present in
`state.md`, that's the signal that the cache has new content not yet
reflected in the map. Refresh before reading — don't read the missing
path on the assumption it's there. The refresh is cheap.

## Common pitfalls

- **Symlinking cache dirs.** Don't. See the "Why this exists" section.
- **Hand-editing `state.md`.** It will be overwritten on next refresh.
  If a row is wrong, the fix is upstream — the plugin's `SKILL.md` needs
  fixing, not `state.md`.
- **Picking "newest" by version string.** Version strings are commit
  hashes, not timestamps. `d1f903fbd013` is not older or newer than
  `a783d99248a7`. Sort by mtime.
- **Forgetting to refresh after a plugin update.** If `state.md` was
  written before a plugin update, paths to pruned versions will be dead.
  The "model encountered a skill name not in state.md" detection is the
  fix; honor it.
- **Running the bash block from a temp file in /tmp/.** Don't. The
  script self-locates via `$0`, so the file the script lives in *must*
  live in this skill's directory. If you need a temp file, copy it to
  `~/.pi/agent/skills/finding-managed-cc-skills/` first; `state.md`
  will land in the right place automatically.
